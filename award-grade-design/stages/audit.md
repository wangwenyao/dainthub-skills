# Stage: audit — 体验与界面审计

## 目的

只分析当前产品质量，不直接修改代码。找出最影响任务成功、信息清晰和视觉品质的问题。

## 输入

- 当前页面或项目
- 用户任务
- 关键用户流程
- 截图 / 浏览器实际渲染（有则优先；模型无法查看图片时按 `references/visual-qa-protocol.md` 的「能力判定与运行模式」降级取证）

## 检查顺序

1. 任务是否能快速完成。
2. IA 与视觉层级是否清楚。
3. 高密度区域是否可扫描。
4. 交互状态是否完整。
5. 设计语言是否一致。
6. 可访问性、响应式与性能是否存在明显问题。
7. 是否存在组件库默认风格或模板化痕迹。

## 产出

`design-audit.md`

按 `templates/design-audit.md` 的章节结构输出。每一项按“问题 → 证据 → 影响 → 优先级 →
建议”记录，证据必须落到具体 page / viewport / state。

不直接改代码。

## 停止条件

```text
五字段记录不完整，或证据未落到具体 page / viewport / state → 未完成：补齐后再交付
没有真实渲染或模型实际可读的截图作证的问题 → 标注「未验证推断」，不得计入 P0 / P1
文本渠道取证（DOM 快照 / computed style / 几何测量）属于真实渲染作证，注明证据渠道后可计入 P0 / P1
P0 / P1 清单完整、逐项可追溯 → 停止：audit 是 read-only Stage，不进入修复
```

作证指模型实际能读取的证据：存在但看不了的截图不作证。截图存在而视觉通道不可用时，
不得宣称已审查该截图——请用户口述截图内容，或改用文本渠道证据（DOM 快照、computed
style、几何测量，见 `references/visual-qa-protocol.md` 的「盲查取证通道」）完成审计；
截图本身归档移交用户，感知项标「未验证（需视觉通道）」。

## 限制

不得借审计之名顺手重做页面。发现范围外问题时记录为 dependency 或 follow-up。
