# Stage: audit — 体验与界面审计

## 目的

只分析当前产品质量，不直接修改代码。找出最影响任务成功、信息清晰和视觉品质的问题。

## 输入

- 当前页面或项目
- 用户任务
- 关键用户流程
- 截图 / 浏览器实际渲染（有则优先）

## 检查顺序

1. 任务是否能快速完成。
2. IA 与视觉层级是否清楚。
3. 高密度区域是否可扫描。
4. 交互状态是否完整。
5. 设计语言是否一致。
6. 可访问性、响应式与性能是否存在明显问题。
7. 是否存在组件库默认风格或模板化痕迹。

## 产出

`design-audit.md`

按“问题 → 证据 → 影响 → 优先级 → 建议”记录，不直接改代码。

## 限制

不得借审计之名顺手重做页面。发现范围外问题时记录为 dependency 或 follow-up。
