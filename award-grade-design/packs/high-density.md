# Pack: high-density

适用于 BI、Dashboard、ERP、CRM、CDP、MA、运营平台、数据平台、科研软件等。

## 核心公式

```text
单位视口信息价值 + 扫描效率 + 层级 + 分组 + 决策有效性
```

密度的目标是让用户在更少的滚动和更短的注视里做出更好的决定，不是把更多像素塞进
屏幕。

## 密度档位

```text
comfortable / standard / compact
```

- 一个界面必须有明确的默认档位，不要让人猜。
- 切换档位要同时改控件高度、行高、内边距与字号；只改其一是假密度。
- 档位是用户可调项时才提供切换，否则固定一档，减少决策成本。
- 表格、列表、工具条可以比正文更紧凑；正文、表单标签、错误信息不要跟着压缩。

## 必须避免的假密度

```text
缩小字号
把行高压到接近重叠
去掉必要的分组间距
把标签改成只留 tooltip
```

这些做法是把信息量转嫁给用户的阅读成本，账面信息量上升，实际可用性下降。

## 扫描路径

高密度页面要能被“扫”，而不是被“读”：

- 一眼定位当前区间的状态（正常 / 异常 / 待处理）。
- 异常与需要动作的项，在视觉上先于中性数据出现。
- 同一屏内同类信息用同一套对齐与格式，让眼球能用同一条路径反复采样。

Dashboard 推荐结构：

```text
Context → Signal → Comparison → Explanation → Exception → Action
```

## Table / Filter / Toolbar

- 列有优先级：默认展示决策必需的列，其余可配置，而不是全塞进去。
- Filter 按任务分组，不要把条件平铺成同等权重。
- Toolbar 区分主操作与低频操作，低频收进溢出菜单。
- 溢出、截断、粘性区域都要有明确策略，不能靠“数据通常没那么长”过关。

## 越界检查

如果为了放更多信息，需要去掉层级、分组或状态提示，说明密度已经超过这个页面该承担
的容量——应该重新切分页面，而不是继续压缩。
