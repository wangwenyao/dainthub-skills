# Pack: ai-workspace

AI Workspace 不默认等于 Chat UI。聊天只是众多形态之一，而且通常不是任务效率最高的
那一种。

## 先判断形态

```text
一次性问答          → 输入框 + 结果区
面向任务的生成/编辑  → 左右分栏：上下文 / 结果
批量或队列式处理     → 列表 + 逐项状态
嵌入现有工作流       → 行内建议 / 侧栏，不要另开一页
需要多轮迭代的产出   → 结果区 + 可回退的版本历史
```

## 必须明确

```text
任务上下文    用户带着什么进来（选中项、筛选条件、当前实体）
输入          自由文本 / 结构化 / 文件
生成结果      结果的形态与可操作粒度
不确定性      置信信息、覆盖范围、可能出错的地方（适用时）
证据 / 来源   结果依据什么得出（适用时）
可执行动作    采纳 / 修改 / 忽略 / 导出
编辑 / 重试 / 撤销
```

## 长任务与流式

- 让用户看到“正在做什么”，而不是一个转圈的图标。
- 部分结果可先用就先呈现，并明确标记哪些部分还不完整。
- 允许中断；中断后要能说清已经完成了什么。

## 失败与不确定性

- 失败要给出可恢复的下一步，而不是只说“出错了”。
- 生成物与人写的内容在视觉上必须可区分，避免被误当作既有事实。
- 任何会改变数据的动作都要可撤销，且撤销入口与执行入口在同一视线范围内。

## 优先任务型 UI

先把“用户要完成什么”表达清楚，再考虑要不要加一个聊天入口。
