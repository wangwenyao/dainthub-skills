# Visual QA Protocol

## 目标

只依据真实浏览器渲染判断视觉质量，不根据源代码想象结果。

真实渲染有两种取证渠道：视觉渠道（模型查看渲染截图的像素）与文本渠道（DOM 快照、
computed style、几何测量、a11y 树、console）。两者都是对真实渲染的观察；感知类审美判断
只有视觉渠道能给出。

审查流程、三层审查、缺陷分级与评分停止条件见 `stages/visual-qa.md`。
本文件只补充能力判定、取证工具与采样范围，不重复流程定义——两处各写一份必然漂移。

## Browser abstraction

可使用环境中现有的任意浏览器自动化能力，例如：

- Playwright
- agent-browser
- browser-use
- 其他等价工具

不把具体工具写死到 Design Spec。

取证输出以文本渠道为准（DOM / computed style / 几何 / a11y 树 / console）；截图文件
生成后归档，作为移交用户查看的证据，而不是模型自己的观察材料。取证渠道由
「能力判定与运行模式」决定，与本节的工具选择正交。

## 能力判定与运行模式

视觉 QA 依赖两项相互独立的能力：

| 简称 | 能力 | 含义 | 取值 |
|---|---|---|---|
| C1 | 浏览器自动化能力 | 能驱动真实浏览器加载页面并取证：DOM 快照、computed style、几何测量、a11y 树、console、生成截图文件 | 可用 / 不可用 |
| C2 | 模型视觉通道 | 当前模型端点能否把图像读入上下文 | 可用 / 不可用 / 未判定 |

C1 缺失不等于 C2 缺失；「自动化可用」从不等价于「可以完成视觉验收」。组合出三种运行模式：

```text
C1 有 + C2 有 → 完整模式：像素审查 + 机械断言
C1 有 + C2 无 → 盲查模式：文本渠道取证；截图照常生成并归档移交用户
C1 无（C2 任意）→ 未验证模式：本地渲染证据缺失，视觉项标「未验证」；
                用户提供的截图若模型可查看，仍可作为作证证据
```

模型视觉通道只能在运行时观测，采用懒判定：会话内首次需要查看图像时，尝试读取该图像
一次。成功 → 视觉通道 = 可用，进入完整模式；失败（如 API Error 400 No endpoints found
that support image input 或等价的图像输入不支持信号）→ 视觉通道 = 不可用：记录会话备忘，
本会话不得再次尝试读图，立即转入盲查模式。网络类瞬时错误允许重试一次，仍失败按不可用
处理并记录判定依据。不做合成的预先探测：任务真正需要查看的第一张图就是最可靠的探针。
判定结果写入报告的「证据渠道」章节；除非用户或宿主明确说明视觉已可用，会话内备忘
不解除——误判方向是安全的：把可用判为不可用只是少看图、多走文本渠道，绝不产生谎报。

统一标注词表：证据渠道字段 `channel: 视觉渠道 / 文本渠道`（可选，省略视为视觉渠道；
盲查模式下必填——缺省的条目不得视为视觉渠道作证，补注后才能计入评分）；
条目判定「已验证（文本渠道）」「未验证（需视觉通道）」「未验证推断」；维度评分
「未评分（无视觉通道）」；Gate Status「DEFERRED（无视觉通道）」；渲染结论「视觉未复核」。
任何模式下不得宣称视觉验收通过。

## 默认截图矩阵

```text
1440 × 900
1280 × 800
1024 × 768
390 × 844（产品支持移动端时）
```

完整模式按视口做像素审查；盲查模式在同一组视口做 DOM 测量（scrollWidth 与
clientWidth、rect 裁剪、几何对齐）与状态断言。自动化可用时（完整 / 盲查模式）截图
始终按矩阵生成并归档供人工复核；未验证模式无本地渲染，按用户提供材料审查。

## 页面采样

至少覆盖：

- Overview / Entry
- Primary Work Surface
- 高密度数据页
- Form / Operation
- Detail
- Empty
- Loading
- Error
- Responsive

## 盲查取证通道

| 通道 | 取证内容 | 覆盖的典型缺陷 |
|---|---|---|
| DOM 快照 / a11y 树 | 结构、语义、name / role / value、焦点顺序、可达性 | 主任务无法完成、严重 Accessibility、关键操作难找 |
| getComputedStyle | 字号、行高、字重、颜色、边框、阴影、动效、间距 | Typography、State、Focus、Micro 层 |
| getBoundingClientRect | 边缘偏差、相邻间距、溢出与裁剪 | 对齐不一致、Responsive 失真、密度 |
| elementFromPoint / z-index | 交互目标是否被遮挡 | 严重视觉遮挡 |
| 程序化对比度 | computed 颜色对计算 WCAG 对比度 | 严重 Accessibility 问题 |
| 状态枚举 | hover / focus / active / disabled / loading / error 的 computed style 差异 | 关键交互或状态错误、组件状态缺失 |
| Token 契约比对 | Token 解析值与元素 computed value 逐一 diff；扫描 Token 集外的硬编码值 | Token 使用不一致 |
| console 与键盘遍历 | 运行时报错、焦点路径 | 实现验证清单各项 |
| 前后 computed style / DOM diff | 局部修改前后对比 | optimization 局部验证 |

盲查模式下 P0 四项（主任务无法完成 / 严重视觉遮挡 / 关键交互或状态错误 / 严重
Accessibility）保持全部可判定，不得以无法看图为由跳过。文本渠道核验的项标
「已验证（文本渠道）」；各级条目的可判定性声明见 `references/visual-defect-catalog.md`
的「渠道可验证性」，两表互为索引、不重复维护。

## 感知项移交与人工复核

以下判断没有文本代理，盲查模式下标「未验证（需视觉通道）」，不得据源码推断后计入评分：
构图与导向、节奏与视觉重量、高密度页面扫描性、Card / Border / Shadow 是否过度、
可选的品牌细节、非关键 Motion 的感知质量。

移交步骤：

1. 按默认截图矩阵生成并归档截图，文件名含页面与视口。
2. 每个感知项写成可回答的问题（如「Table 表头与筛选区的主次是否清楚」），附在报告的
   「人工复核移交」章节。
3. 用户答复前，相关维度在评分中标「未评分（无视觉通道）」，Gate Status 标
   「DEFERRED（无视觉通道）」。
